# Illager Archmage / Архимаг иллейджеров

В игровой версии **0.43** Архимаг держит настоящий предмет **Эмрис**, отдельно от модели тела. Нативный экспорт содержит 37 кубоидов тела и пустую привязку `staff` в руке; прежние 13 кубоидов золотого посоха остаются в `.bbmodel` только как редактируемый художественный образец. Руки при ходьбе направлены вперёд, плащ отведён назад. Анимации в этом проекте и Java-экспорте обновляются одним генератором. Существующие изображения поз показывают художественную модель с исходным посохом; [настоящий игровой кадр с Эмрисом](../MahouTsukai-Fabric/docs/screenshots/0.43/archmage-emrys.png) и [отчёт 0.43](../MahouTsukai-Fabric/docs/QA-0.43.md) описывают текущую интеграцию.

Редактируемая кубическая модель по предоставленному концепту: серое лицо иллейджера, длинный нос, зелёные глаза, чёрная мантия, золотые наплечники, плащ с руной и посох с золотым кристаллом.

## Файлы

- `models/illager_archmage.bbmodel` — основной проект Blockbench, формат 5.0, Generic Model; геометрия, две встроенные текстуры и все 14 анимаций.
- `textures/illager_archmage.png` — настоящий RGBA-атлас 256×256.
- `textures/staff.png` — настоящий RGBA-атлас 128×128.
- `animations/*.json` — читаемые исходные кривые проекта (не формат GeckoLib).
- `model-source.json` — геометрия, иерархия и анимационные данные генератора.
- `previews/front.png`, `back.png`, `side.png` — ортографические изображения настоящей геометрии с её UV-текстурами, не концепт-арт.
- `previews/animation-poses.png` и `pose-*.png` — 14 ключевых поз того же рига; персонаж и посох трансформированы реальными кривыми.
- `validation.json` — результат автоматической проверки исходного проекта.

Высота тела — 48 единиц, то есть 3 блока. Верхушка посоха достигает 52 единиц. 50 кубоидов, 10 групп, 300 граней, 948 ключевых кадров, включая движение кисти. Каждая грань имеет отдельный окрашенный участок атласа, без случайных UV-пересечений.

## Иерархия и анимации

`root_motion` объединяет тело и ноги для появления, парения и падения. `body` несёт `head`, обе руки, `shoulder_armor`, `cloak`. `staff` вложен в `right_arm`; его pivot находится внутри правого кулака, а ось древка проходит через этот pivot. Компенсация поворота кисти удерживает посох вертикально в спокойной стойке, при ходьбе и обычном парении. Во время атак, появления и реакции на удар посох намеренно наклоняется и движется вместе с кистью. Отдельные pivots находятся у шеи, плеч, бёдер и крепления плаща; координаты сохранены в модели.

| Анимация | Длительность | Реализованное движение |
| --- | --- | --- |
| idle | 4 с, цикл | Дыхание, поворот головы, движение плаща |
| walk | 1,2 с, цикл | Противофаза рук и ног, плащ; сдержанное движение руки с вертикальным посохом |
| cast_spell | 1,4 с | Подготовка клыков: левая рука вперёд, наклон головы |
| staff_attack | 0,8 с | Замах посохом, разворот корпуса |
| levitation | 3 с, цикл | Подъём всего персонажа, раскрытие рук и плаща |
| summon_pillars | 1,6 с | Подъём и опускание рук, взмах плаща |
| area_attack | 1,5 с | Разворот корпуса и широкий взмах |
| golden_volley | 1,6 с | Прицеливание открытой левой рукой, поворот корпуса и головы |
| summon_vex | 1,6 с | Левая рука над головой, раскрытие плаща, взгляд вверх |
| arrive | 2,5 с | Выход из земли, разворот к цели, раскрытие плаща и поднятие рук; окончание на исходной высоте |
| hurt_reaction | 0,35 с | Короткий наклон корпуса и головы, вздрагивание рук и плаща |
| cast_recovery | 0,6 с | Плавное опускание рук и возврат посоха в вертикальное положение после заклинания |
| combat_idle | 3,2 с, цикл | Боевая стойка, разворот плеч и движения рук; выразительнее ниже половины здоровья |
| death | 1 с | Падение всей модели, головы, руки и плаща |

В игровом рендерере пять видов заклинаний имеют отдельные позы и жесты посоха: `1 → cast_spell`, `2 → summon_pillars`, `3 → golden_volley`, `4 → area_attack`, `5 → summon_vex`. Каждая дорожка растягивается на серверные 32 тика подготовки. После выпуска — 12 тиков `cast_recovery`, чьи начальные положения рук и кисти совпадают с окончанием каждой атаки. Появление запускается синхронизированным таймером в 50 тиков; после него модель возвращается к точной исходной высоте, не остаётся парить. Урон и появление сущностей определяет сервер; файл модели не выполняет атаки самостоятельно.

## Minecraft / Fabric

Целевая среда проверена по проекту: **Minecraft 26.1.2, Fabric Loader 0.19.5, Fabric API 0.155.3+26.1.2, Java 25**.

GeckoLib не требуется. `.bbmodel` является исходником для редактора и не загружается игрой напрямую. Генератор `scripts/build_archmage.py` экспортирует тот же набор кубоидов/UV/кривых в нативный `ArchmageModel.java` на `ModelPart` и собирает атлас 512×256 с отдельной картой свечения глаз/кристалла. Рендерер — `RenderRealityMarbleBoss.java`.

Сущность сохраняет ID `mahoutsukai:reality_marble_boss`, чтобы существующие сохранения продолжали её узнавать. В игре имя заменено на Архимага, зона попадания — 1,5×3 блока, здоровье — 400. Босс появляется в Reality Marble и выдаёт Morgan по серверному правилу однократной награды.

Редактор и игра используют одни ключи: основные кривые — smoothstep (Bezier с горизонтальными ручками на трети интервала в Blockbench), дополнительные ключи кисти — линейные, с частотой 40 кадров/с. При смешивании спокойной стойки, ходьбы и парения игровой рендерер дополнительно вычисляет точную обратную ориентацию руки. В исходных спокойных дорожках максимальный измеренный наклон — 0,034°. Во время пяти заклинаний посох совершает отдельные жесты с максимальным наклоном 35–49°, а не застывает вертикально. Экспорт из произвольно отредактированного `.bbmodel` обратно в Java автоматически не реализован: для изменений игрового рига правьте канонический генератор и пересоздавайте проект.

## Воспроизведение проверок

Из корня репозитория, Python с Pillow:

```powershell
python -X utf8 scripts/build_archmage.py
python -X utf8 scripts/validate_archmage.py
```

Валидация проверяет UUID, иерархию, положительные размеры кубов, pivots, границы и пересечения UV, непрозрачность пикселей всех граней, совпадение встроенных PNG с файлами, 14 непустых анимаций и непрерывность циклов. Дополнительно проверены 4411 промежуточных ориентаций посоха, ограниченный наклон в пяти заклинаниях, крепление pivot к кулаку и совпадение оси древка с pivot. Проверены непрерывность перехода из каждой атаки в восстановление и возврат появления на исходную высоту. Игровые проверки выполняются отдельно; структурная валидация и изображения ключевых поз не заменяют проверку в клиенте.

**Открытие в самом Blockbench пока не подтверждено:** доступ к веб-редактору ранее блокировался браузерной политикой. Для ручной проверки откройте `.bbmodel` в Blockbench 5.x, перейдите в Animate и воспроизведите 14 дорожек. Не выдаём структурную проверку за проверку редактором.

Официальное описание исходного формата: [Blockbench bbmodel specification](https://www.blockbench.net/wiki/docs/bbmodel/).
