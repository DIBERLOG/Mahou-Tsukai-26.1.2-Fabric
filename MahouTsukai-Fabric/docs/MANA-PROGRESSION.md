# Перенос прогрессии маны — fabric.0.3

Из PlayerManaManager.updateManaCounter и increaseMaxMana выделена исходная
арифметика в ManaProgression.recordSpent. Сохраняются счётчик до следующего
увеличения, перенос перерасхода, коэффициент от максимума, предел счётчика,
линейное/логарифмическое наказание, исходное округление и предел максимума.

Метод меняет максимум и счётчик, но не расходует и не восполняет текущую ману.
Он пока НЕ вызывается из игровых заклинаний: полный PlayerManaManager.drainMana
должен быть перенесён вместе с самоцветами, батареями, FakePlayer и условиями
урона владельцу. Вызывать упрощённый расход вместо него не добавлялось.

Перенесены две оригинальные команды с правами gamemaster:

- `/maxmahou <player> <mana>` — устанавливает максимум и текущую ману.
- `/addmaxmahou <player> <mana>` — увеличивает максимум и заполняет ману.

Обе сбрасывают счётчик до MANA_UP_COUNTER и отправляют исходный PlayerMahouPacket.
Как и в оригинале, администраторские команды не используют MAX_MANA_CAP;
этот предел применяется формулой игрового роста. Известное поведение исходного
int-сложения команды addmaxmahou не заменялось другой числовой моделью.

## Конфигурация

При запуске сервера создаётся файл внутри конкретного мира:
`serverconfig/mahoutsukai-fabric-mana.json`. Это новая Fabric-конфигурация только
подмножества прогрессии, а не автоматический импорт всего NeoForge TOML.
Отсутствующие поля получают оригинальные значения по умолчанию, существующий
файл при чтении не переписывается. Изменения применяются после перезапуска.

| Ключ | Исходное значение | Исходный диапазон |
|---|---:|---:|
| MAX_MANA_CAP | 200000 | 0–100000000 |
| MANA_UP_COUNTER | 100 | 1–100000000 |
| MANA_UP_COUNTER_RATIO | 0.0 | 0–100000000 |
| MANA_UP_COUNTER_MAX | 100 | 0–100000000 |
| MANA_INCREASE | 1 | 0–100000000 |
| MANA_INCREASE_LOG_PUNISHMENT | false | boolean |
| MANA_INCREASE_PUNISHMENT_FACTOR | 0.0 | −10000000–10000000 |

Ошибочный тип, дробь вместо целого, переполнение int, неизвестный ключ или выход
за диапазон останавливают запуск с сообщением о конфигурации; баланс не
сбрасывается молча. Диапазоны сверены с SERVER builder исходного MTConfig.

## Проверки

- Сборка и автоматические проверки прошли.
- Порог 99+1, перерасход 350, ограничение максимума, ratio и логарифмическая
  поправка проверены на известных ожидаемых результатах.
- Создание конфигурации, частичный override, сохранение defaults и отклонение
  неверных значений проверены в отдельном временном каталоге.
- Сервер загрузил world config; команды выставили 250, затем 275.
- Настоящий клиент получил соответствующие пакеты 250/250 и 275/275.
- Изменённое значение записано в player .dat. Проверка файла выполняется через
  `gradlew savedPlayerCheck -PexpectedSavedMana=275`.
- Попытка `execute as Player733` из RCON сохраняет права консоли и не доказывает
  запрет команды для обычного игрока. Проверка неоператора через UI не завершена.
- Повторная проверка возрождения с 275 была прервана пользовательским вводом в
  окно Minecraft. Серверные команды подтверждают состояние 275 у умершего игрока;
  это не считается успешным тестом возрождения. Тест возрождения с 100/100 в 0.2
  выполнен отдельно и остаётся зафиксированным в отчёте.

Расход, восстановление, Leylines/Geas/William, самоцветы и батареи остаются
следующей работой. Их отсутствие не маскируется формулой прогрессии.
