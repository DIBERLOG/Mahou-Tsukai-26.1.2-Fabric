# Связанный перенос самоцветов и батарей — fabric.0.5

Этап существенно расширяет работающую часть, но **не доказывает готовность
половины Mahou Tsukai**. Заклинания и оружие пока не перенесены. Самостоятельно
приписывать готовность по числу файлов или по наличию восстановленных ресурсов
нельзя.

## Подключённое поведение

- Attuner, AttunedDiamond и AttunedEmerald зарегистрированы с оригинальными ID,
  моделями, текстурами, рецептами, ёмкостями, полосой заполнения и подсказкой.
- Зарядка использует оригинальную формулу ceil(maxMana * chargeRate), предел
  ёмкости, расход из личного запаса/доступных батарей и увеличение максимума.
- Перенесена группа методов PlayerManaManager до regenMana: поиск самоцветов,
  суммирование, расход, батареи, их зарядка, проверка владельцев, общедоступность
  fae, on/off и инверсия redstone. Порядок обычного расхода — игрок, самоцветы,
  затем батареи. Ветви частичного/недостаточного расхода сохранены.
- Прогрессия применяется к личной потраченной мане, как в оригинале.
- Перенесены оба блока батарей и block entities. Имена NBT и item components
  сохранены. Loot tables переносят владельца и заряд в выпавший предмет;
  установка предмета восстанавливает эти значения.
- SafeFakePlayer использует настоящий Fabric FakePlayer, а не имитацию NPC.
  Донорский запас и исходные методы создания сохранены. Поведение FakePlayer
  во всех заклинаниях отдельно ещё не проверялось.
- Команда /addmahou перенесена вместе с исходными ветвями расхода и урона при
  нехватке. Остальные ранее подключённые команды сохранены.
- World config mahoutsukai-fabric-economy.json содержит исходные значения и
  диапазоны подключённой части. Проверка атомарна: ошибочный файл не применяет
  половину новых значений. Ёмкости передаются клиенту отдельным Fabric-пакетом.

## Оригинальная графика

Перенесены ManaCircuitRenderer, ManaCircuitMagitechRenderer, состояние рендера,
отрисовка колец NewRenderUtils и связанные фабрики RenderType. Восстановлены
специальные модели предметов для обоих circuit-типов. Сохранены исходные вершины,
вращения, цвета, размеры колец, текстуры и параметры конвейеров.

NeoForge RenderPipeline.toBuilder заменён копированием доступных vanilla-свойств.
Access widener в namespace official открывает только фабрику RenderType, её имя
и таблицу special model codecs. Остальные обёртки рендера всего оригинального
мода пока не подключены. Удалён неподдерживаемый vanilla parent builtin/entity
из исходных item JSON; геометрия и display transforms сохранены.

Графика проверена в настоящем клиенте: батарея рисует цветные вращающиеся кольца,
магитех-батарея — исходный корпус и внутреннее свечение. Снимок игры:
screenshots/circuit-rendering.png. Это не созданный макет.

## Проверки

`runEconomyChecks` запускает отдельный test-only mod на настоящем dedicated
Fabric-сервере в run/economy-checks. Он не включён в production JAR.
Тестовый сервер привязан к 127.0.0.1:25587; EULA ранее принята пользователем.

Подтверждено:

1. Из 1000 личной маны заряженный самоцвет получает 100, у игрока остаётся 900,
   максимум увеличивается до 1001.
2. При 30 личной маны, 70 в самоцвете и 200 в батарее расход 150 оставляет
   0 / 0 / 150. Счётчик прогрессии учитывает только 30 личной маны.
3. При недостатке общего запаса обычный запрос оставляет ресурсы нетронутыми.
4. Чужая батарея не расходуется; fae-доступ разрешает использование.
5. Выключенная батарея исключается; redstone инвертирует on/off.
6. Настоящий ItemStack.copy не получает изменения через копию GemMahou до
   явной записи; запись в копию не меняет оригинальный предмет.
7. Loot table сохраняет владельца и 150 маны в item components.
8. Повторное применение компонентов выпавшего предмета восстанавливает владельца
   и 150 маны в новой батарее.
9. Форматы данных, world config, синхронизация ёмкостей и прежние проверки проходят.

Журналы: economy-verified.log, economy-integration-final.log,
economy-client.log, economy-visual-checks.txt. В первом клиентском журнале exit -1
возник из-за завершения тестового процесса после проверки, а не считается
успешным штатным выходом клиента. В нём также есть ожидаемая ошибка получения
profile key с dev-сессией и первоначальное предупреждение builtin/entity;
неподдерживаемый parent затем удалён.

Финальная попытка подключения 0.5 стартовала до готовности сервера и получила
Connection refused. Это не считается успешной проверкой подключения. Во время
повторной попытки пользователь остановил Computer Use клавишей Escape; ввод
прекращён. Проверка новых ёмкостей выполнена кодеком и применением на клиентских
полях в автоматическом тесте, но отдельного визуального подтверждения финального
повторного подключения не заявляется.

При подготовке площадки персонаж тестового мира оказался внутри terrain и погиб.
Это не тест DOOM и не ошибка механики маны. Площадка затем создана на высоте 250,
проверка проведена в creative; в снимке видны исходные кольца. Все такие изменения
относятся только к тестовому миру. Рабочий сервер и пользовательские миры не менялись.

## Ограничения и следующие системы

- getManaRegen и обычное восстановление раз в 100 ticks ещё не подключены:
  исходный метод включает Leylines, Geas, William и появление Fae. Их нельзя
  заменить упрощённым +1 без изменения оригинала.
- Рецепт обычной Mana Circuit требует Fae Essence, поведение которой включает
  рисование магического круга. Она ещё не перенесена, поэтому этот рецепт пока
  не включён. Магитех-батарея и самоцветы используют оригинальные доступные рецепты.
- Переключение режима fae через Fae Essence и полный интерфейс конфигурации
  остаются частью переноса кругов/существ. Серверная семантика fae-флага проверена.
- В ветви collectImplicitComponents пропущена запись null-владельца: null не
  имеет корректного представления в DataComponentMap. Владение после назначения
  и повторной установки сохранено.
- Сканирование батарей сохраняет исходные границы X/Z и поведение getChunk;
  оптимизация загрузки чанков и большие пользовательские диапазоны не проверены.
- Взрывы, боевые заклинания, оружие, существа, HUD и DOOM ещё не готовы.


## Обновление 0.6: восстановление во сне

Перенесена ветка sleep из PlayerManaManager.regenMana и условия
ServerHandler.playerSlept / ManaEvents.mahouSleep. Native stopSleepInBed
подключён через PlayerMahouMixin: оба флага должны быть false; время
overworld clock по модулю 24000 должно быть >23998 либо <12500, без грозы.
Восстанавливается int(MANA_RECOVERY_SLEEP * maxMana), по умолчанию половина.
Сохраняются ограничение запаса, штраф за души даже при полном запасе,
потеря значения одной души игрока при отрицательном восстановлении и
исходное сообщение mahoutsukai.help.too_many_souls. Для тестового игрока
без соединения пропускается отправка сообщения, арифметика сохраняется.

Четыре настройки добавлены в серверный economy JSON. Для
DEATH_COLLECTION_DRAIN_PER_SOUL взят действительный default SERVER builder
1.0 и диапазон 0..10000000: статическое поле оригинала 0.1 заменяется
настройкой при загрузке. Остальные defaults: MANA_RECOVERY_SLEEP=0.5,
DEATH_COLLECTION_SOUL_VALUE_PLAYER=1.0,
DEATH_COLLECTION_NEGATIVE_REGEN_PUNISHMENT=true.

runEconomyChecks проверяет native wake hook, флаги прерывания, время,
грозу, предел маны, штрафы за души и изменение доли восстановления.
Обычная периодическая регенерация пока не подключена.
